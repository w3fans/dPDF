region; request envelopes carry view generation to cancel stale work. Native
PDFium objects remain on the existing owner thread. Use a small destination
bitmap with a negative native origin and the form-data render path; matrix/clip
configuration would disable form-field rendering. No flattening or document
mutation is permitted. Existing layout/transforms continue to place selections,
search results, marks and review overlays.

Cover complete tile coverage, bounded overscan/bytes, fractional viewport edges,
all rotations, crop offsets and UserUnit; compare stitched detail with an exact
full reference including forms/annotations. Qualify rapid pan/zoom/tab changes,
stale completion rejection, native landmarks, memory plateau and ordinary-path
performance. Required hosted native/compiler/runtime checks remain pending; no
local Rust/C++ compilation.

## Development implementation

The draft includes a bounded viewport planner, 510-pixel tile cores with one-pixel
gutters and native negative-origin rendering into small bitmaps. Eight global
permits cover queued/active render work and unconsumed replies across generation
changes. Detail is layered below selections/search/mark/review overlays without
changing their document transforms. Generated source contracts and formatting
are checked locally; compilation and native execution use hosted public CI.

New native diagnostics compare 76 generated full-transform/stitch cases and
exercise real windows in twelve view/rotation combinations at scale 1/1.5/2,
including panning, rapid zoom generations and tab switch/closure. Their presence
is not a passing result. GUI latency, memory plateau, ordinary-path regression
comparison and operator acceptance remain pending until measured.

Draft [PR #26](https://github.com/w3fans/dPDF/pull/26) targets `main` because
the existing public CI workflow filters pull requests to that branch. Initial
source 0911e4f04873364170704de8d2d81dccbe5259ac passed hosted repository policy
and script contracts. Its first Linux compile failed; source inspection found
the new diagnostic calling `update_render_window` instead of the existing
`request_visible` controller method. The follow-up corrects those calls and
adds diagnostic presentation timings and 50ms Linux RSS observations. Native
results remain pending; sampled RSS is not an exact process peak or a plateau.

`scripts/compare-reader.py` alternates parent/candidate execution order across
repeats on the same immutable generated fixtures and native library, retaining
all raw runs and executable/input hashes. A three-repeat same-executable driver
check completed all six fixtures, with two timing medians over the proposed
10% guard due to measurement variability (vector zoom and mixed-geometry last
page). This check validates the driver, not a candidate result; retain flagged
candidate cases for further repetitions/investigation rather than raising the
guard or declaring a pass.

Retained first-run compiler logs also identify missing `Vec` type inference for
the new Slint model collection and a newly deprecated `AtomicUsize::fetch_update`
on hosted stable Rust. Specify the collection type and use the longstanding
compare-exchange loop so both hosted stable and declared Rust 1.92 remain
supported without suppressing warnings or raising the minimum version.

The next hosted Clippy pass reached the native oracle and required `as_chunks`
for fixed RGBA groups under stable Rust 1.100. Use that API (available before
1.92) without changing the byte comparison, tolerances or supported minimum.
The window fixture now uses distinct supported 400/550/600% generations rather
than values silently clamped by the existing 600% reader maximum.
